## 2. Что сделано в цикле 1.0.13 — не переделывать

выданный **до** последней правки продюсера. Формально всё было в порядке

по коду, который продюсер потом переписал, и подмены в журнале видно не было:

## 4. Грабли

Три дня ушло на то, чего не следовало делать. Чтобы не повторить.

1. **Вердикт — по хешам, а не по порядку событий.** Порядковое правило («вердикт
   должен быть позже последней сдачи») даёт ложные срабатывания: событие
   `VERIFY` переиспользуется при повторном approve, и его позиция старая при
   свежем решении. Правильная связь — хеши артефактов в `VERIFY`/`REWORK`.
2. **Точечный writable-биндинг файла ломает атомарную запись.** Файл,
   смонтированный на себя, становится точкой монтирования, и `rename` поверх
   него даёт `EBUSY`. Агент не сможет записать файл вообще. Защита
   накладывается сверху: ro-bind поверх записываемого родителя.
3. **`lru_cache` на пробе, которую подменяют тесты, — ловушка.** Кэш
   переживает замену: подменённая проба вернёт «правдивый» ответ, который
   потом уедет дальше по процессу. Пробы должны оставаться чистыми.
4. **`--timeout` в `addopts` ломает проверку sdist.** В джобе `build` для
   sdist ставится только `pytest`, без dev-экстра, и опция становится
   неопознанной. Таймаут — в команде CI, а не в конфиге pytest.
5. **`install` без `-D` падает там, где нет `/usr/local/libexec`** (свежая
   машина, CI-раннер). Это была и документированная команда для оператора.
6. **Проба `systemd-run --system` стоит 25–30 секунд на машине, где systemd
   не отвечает.** `factory doctor` звали десятки раз — и каждый раз он ждал.
   Таймаут уменьшен до 10 с.
7. **Отменённый по таймауту CI-job не отдаёт логов.** Диагностировать придётся
   по косвенным признакам. `--timeout=180` в CI — чтобы зависший тест упал
   внутри себя, со своим трейсбеком.
8. **Кэш конфигурации ключуется по `(путь, mtime_ns, размер)`** — изменившийся
   файл читается заново. Не кэшируй по имени файла.
9. **В эталонном прогоне `metrics.json` содержит замеры wall-clock** — каждая
   пересборка даёт дифф. Это ожидаемо, не чинить.
10. **Образ раннера меняется без предупреждения.** 16 ноября джоб `integration`
    упал на `apt-get install policykit-1`: пакет переименован в `polkitd`, а
    `policykit-1` на текущем образе — транзиционный пакет без кандидата. Стоит
    ставить `polkitd` с откатом на `policykit-1`. Тот же класс проблем: образ
    раннера может обновиться в любой момент, и упавший джоб — это не про код.

## 5. Правила проекта

Из `AGENTS.md` (читать перед работой ✓):

- **Девять законов** в §2. Особенно: журнал пишется только через CLI
  (`factory/journal.py`), ручная правка `state.json` запрещена, `PASS` пишет
  только `02-independent-verifier`.
- **Роли и границы записи** в §4: `02-independent-verifier` не имеет права
  `code` и не правит продукт; `16-security-engineer` пишет лог скиллов;
  `21-technical-writer` пишет только продуктовую документацию.
- **Запреты** в §7: не запускать `factory init` без явной команды человека;
  не публиковать релиз без `gate_s7`; не менять `factory/pipeline.yaml`,
  `factory/roles/` и инварианты без человеческого коммита.
- **Ponytail**: чужие правки не переписываются без нужды, каждый шаг — атомарный
  коммит с проверкой.

Привычки репозитория:

- коммит — одним предложением о том, что изменилось, с абзацем «почему»;
- версия живёт в `VERSION`, `factory.__init__.py` и десяти местах документации;
- `docs/audit/` — evidence: аудит, план цикла, план предыдущего;
- CI: `doctor`, `pytest`, проверка примера, сборка пакета, и отдельный джоб
  `integration` с живой границей.
