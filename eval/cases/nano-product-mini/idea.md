# Продукт: pfu из proxy-for-ubuntu

Реальный Rust-крейт `pfu` (общая библиотека системного прокси для Ubuntu:
конфиг, правила, подписки, движок). Исходники уже лежат в `product/` — это
настоящий код продукта, а не заготовка.

# Что нужно изменить

Раздел `limits` в конфиге задаёт глобальные `rate_limit` и `max_connections`,
а `limits.outbound.<имя>` — переопределения для отдельного канала. Сейчас
слияние «глобальные + переопределение» живёт прямо в `Engine::build`
(`product/src/engine/router.rs`), а опечатка в имени outbound'а в
`limits.outbound` молча игнорируется: конфиг проходит валидацию, лимит не
действует, пользователь узнаёт об этом только по неработающему ограничению.

Нужно небольшое изменение в `product/src/config.rs` и одном вызове в
`product/src/engine/router.rs`:

- `LimitsConfig::effective_for(name)` — действующие лимиты одного outbound'а:
  переопределение из `limits.outbound.<имя>` поверх глобальных `rate_limit` и
  `max_connections`. Незаданное поле наследует глобальное; `rate_limit: 0`
  по-прежнему значит «без ограничения» (`None`); для неизвестного имени
  возвращаются глобальные значения.
- `Config::validate` и `Config::validate_for_read` отвергают ключ
  `limits.outbound`, который не совпадает ни с одним объявленным outbound'ом:
  ошибка называет этот ключ. Тихая опечатка — дефект конфигурации.
- `Engine::build` собирает `outbound_limits` через `effective_for`, а не
  дублирует слияние. Набор лимитов и поведение (включая существующий тест про
  `max_connections`) не меняются.

Тесты — в `#[cfg(test)] mod tests` изменяемых файлов, существующие 218
unit-тестов должны остаться зелёными. Новых зависимостей и сетевых установок
нет.
